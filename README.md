# 인천대학교 연속간행물실 근무 대시보드

Flask + Gunicorn + SQLite로 실행하는 근무 관리 서비스. 화면과 API를 한 컨테이너에서 제공하며 데이터는 Docker 볼륨에 보관한다.

- 30분 눈금의 스크롤 없는 주간 시간표, 현재 구간 표시, 시간표 탭의 주당 근무 시간
- 이전·현재·다음 근무자의 데스크·대기 구분, 다른 주 시간표 복사
- 근무자 이름·전화번호·재직 상태 관리, 이슈 작성·완료
- 관리자·근무자 권한, 계정 관리·비밀번호 변경, DB 백업 다운로드
- Pretendard 글꼴·인천대학교 Blue/Yellow를 사용한 가독성 중심 대시보드
- 연도별 월간 태깅 완료 표, 월별 과월호 담당 추첨·신문사별 완료 체크

## 실행

Python 3.12, `pip install -r requirements.txt`.

첫 개발 실행 전 `python scripts/fetch-font.py`로 공식 Pretendard 1.3.9 글꼴을 준비한다. Docker 빌드와 로컬 실행 도구에서도 자동 수행하며 SHA-256을 검사한다. 운영 중에는 글꼴도 자체 서버에서 제공한다. 글꼴 라이선스는 `static/fonts/OFL.txt`에 포함한다.

필수 환경변수:

| 이름 | 용도 |
| --- | --- |
| `SECRET_KEY` | 32자 이상의 무작위 세션 서명 키. 재시작·배포 시 동일하게 유지 |
| `ADMIN_USER` | 첫 실행 때 생성할 관리자 아이디 |
| `ADMIN_PASSWORD` | 초기 비밀번호, 10자 이상. 저장소나 이미지에 넣지 않음 |
| `DATABASE` | 기본 `/app/data/library.sqlite3` |
| `APP_BASE_PATH` | 기본 `/libaryDashBoard` |
| `COOKIE_SECURE` | 운영 `true`, 로컬 HTTP 개발 때만 `false` |
| `INITIAL_SCHEDULE_JSON` | 선택 사항. 첫 실행 때만 가져올 근무자·시간표 JSON |

```bash
gunicorn --bind 127.0.0.1:8000 --workers 1 --threads 2 'app:create_app()'
python -m unittest discover -s tests -v
```

`seed.json`은 빈 템플릿이다. 실제 근무자·시간표·전화번호는 공개 소스에 포함하지 않는다. 초기 데이터는 비공개 환경변수로 넣는다. 기존 DB가 있으면 초기 데이터·관리자 환경변수로 덮어쓰지 않는다. 비밀번호 변경은 로그인 후 계정 메뉴에서 한다.

## Server Desk 배포

`main` push → GitHub Actions 테스트 → `ghcr.io/eatyummydance200/library-dashboard:main` 및 커밋 SHA 태그 게시. 배포는 Server Desk에서 실행한다. 비공개 GHCR 패키지는 기존 Server Desk에 읽기 자격 증명을 설정해야 하며, 공개 패키지는 익명 pull 가능 여부를 확인한다.

| 항목 | 값 |
| --- | --- |
| 앱 이름 | `library-dashboard` |
| 호스트 포트 | `8090` |
| 컨테이너 포트 | `8000` |
| 바인딩 | `127.0.0.1` |
| 상태 확인 | `/libaryDashBoard/healthz` |
| 볼륨 | `data:/app/data` → `sd-library-dashboard-data` |
| 자동 업데이트 | 초기 꺼짐 |

Funnel 루트는 기존 Server Desk에 유지하고 새 경로만 추가한다. Funnel이 mount 접두 경로를 제거하므로 대상 URL에 동일한 접두 경로를 넣는다.

```bash
sudo tailscale funnel --bg --https=443 \
  --set-path=/libaryDashBoard \
  http://127.0.0.1:8090/libaryDashBoard
```

초기 서버에서 레지스트리 연결 전 기동이 필요하면 `python scripts/deploy.py bootstrap`으로 같은 앱 등록과 로컬 이미지 기동을 수행한다. 이미지 게시 후 `python scripts/deploy.py deploy`로 Server Desk 이미지 배포에 전환한다. 두 명령은 비공개 `.runtime.env`와 기존 관리 서비스의 `.env`를 사용하며 비밀값을 출력하지 않는다.

외부 주소의 `/libaryDashBoard`는 `/libaryDashBoard/`로 이동한다. 로그인·정적 파일·API·쿠키 모두 해당 경로를 사용한다.

## 데이터 규칙

근무일과 정수 분으로 시간표를 저장한다. 시작 포함·종료 제외이며 같은 사람의 겹치는 근무는 저장할 수 없다. 오픈은 09:00에 근무한 사람, 마감은 21:00까지 근무한 사람을 날짜별 한 번씩 센다. 일반·데스크 역할 변경은 별도 구간으로 저장한다.

다른 주 복사는 대상 주가 비어 있을 때만 허용하며 원본 주를 바꾸지 않는다. 재직 비활성화는 과거 근무를 삭제하지 않는다. 이슈 조회는 최근 200건이다.

## 백업과 복구

관리자 화면에서 DB 백업을 다운로드할 수 있다. 서버에서는 다음 명령이 SQLite backup API로 일관된 스냅샷을 만들고 7일 이전 스냅샷을 정리한다.

```bash
docker exec sd-library-dashboard python /app/scripts/backup.py
```

설치용 systemd service/timer는 `ops/`에 있다. 매일 한국 시간 04시에 실행한다. 같은 볼륨 안의 백업은 디스크 고장에 대비하지 못하므로 다운로드한 백업을 별도 기기에 보관한다.

복구 시 서비스를 중지하고 현재 데이터 디렉터리 전체를 먼저 보관한다. 백업 파일의 `PRAGMA integrity_check`를 확인한 뒤 DB를 복원하고, 이전 DB의 `-wal`, `-shm` 파일이 새 DB와 섞이지 않도록 제거한다. 파일 소유자는 컨테이너 사용자 UID 10001로 유지한다. 그 후 서비스를 시작해 로그인·시간표·이슈를 확인한다. 이미지 롤백은 DB 변경을 되돌리지 않는다.

## 제한

한 서버·한 앱 프로세스·소규모 팀을 기준으로 한다. 여러 서버에서 동시 쓰기나 컨테이너 수평 확장이 필요하면 SQLite를 재검토한다. Funnel의 경로 분리는 별도 출처 격리가 아니므로 같은 도메인의 Server Desk와 보안 경계를 공유한다.

## 시간표와 월별 태깅

대시보드는 근무 현황과 이슈만 표시한다. 시간표는 시간표 탭에서 30분 눈금 위에 연속 근무를 하나의 블록으로 표시한다. PC는 월~금 전체, 휴대폰·좁은 태블릿은 요일 선택으로 하루 전체를 표시하며 시간표 내부 스크롤은 없다. 현재 시각은 실제 한국 시간을 기준으로 표시한다. `주당 근무 시간`은 PC에서는 시간표 오른쪽의 작은 표에서, 좁은 화면에서는 시간표 아래에서 선택한 주의 총 시간·데스크 시간·오픈·마감을 집계한다.

태깅 탭은 연도별 근무자 × 1~12월 표다. 관리자가 셀을 누르면 완료 `○` / 미완료 `—`가 즉시 서버에 저장된다. 근무자 계정은 조회만 가능하다. 기존 태깅 표는 제공되지 않았으므로 최초 상태는 미완료이며, 과거 기록을 임의로 채우지 않는다. 비활성 근무자의 저장 기록도 해당 연도에 보존한다.

DB 버전 1은 시작 시 월별 태깅 테이블을 추가해 버전 2로 올린다. 기존 근무자·근무·이슈·계정은 유지한다. 버전 2 DB를 지원하지 않는 이전 이미지로 되돌릴 때는 배포 전 백업도 함께 복원해야 한다.

## 월별 과월호

과월호 탭의 월 선택 → 관리자 `무작위 추첨`으로 사진에 있는 7개 묶음(20개 신문사)을 재직 근무자 7명에게 하나씩 배정한다. 서버의 `secrets.SystemRandom`으로 무작위 배정하고 한 트랜잭션에 저장한다. 같은 월은 한 번만 추첨할 수 있고, 동시 요청도 하나만 성공한다. 추첨 대신 `수동 입력`으로 번호별 담당자를 지정할 수도 있으며, 저장 후에는 `담당자 수정`으로 변경한다. 7개 묶음마다 서로 다른 근무자를 한 명씩 지정한다. 추첨 결과는 이름·신문사 목록을 당시 값으로 보관해 이름 변경이나 비활성화 뒤에도 과거 기록이 유지된다. 처음 배포할 때 기존 달의 추첨·완료 기록은 임의로 채우지 않는다.

신문사별 체크박스로 완료·미완료를 저장한다. 완료 시 체크한 계정과 한국 시간 표시용 시각을 기록하고, 해제하면 완료 표시를 지운다. 관리자는 전체를 수정할 수 있다. 근무자 계정은 인적관리 → 계정 관리에서 본인 근무자를 연결해야 자신에게 배정된 항목만 수정할 수 있다. 새 계정을 만들면서 연결하거나 기존 계정의 연결 근무자를 바꿀 수 있다. 연결 변경 시 해당 계정의 기존 로그인을 만료시킨다.

현재 7개 묶음은 사진의 번호와 신문사 약칭을 그대로 사용하며, 추첨에는 재직 근무자 7명이 필요하다. 사다리 애니메이션·재추첨·자동 예약 추첨은 제공하지 않는다. 월별 추첨은 담당자가 버튼으로 실행하며 과거 달은 월 선택으로 조회한다. 번호·담당자·신문사별 체크·완료 수를 7행 표로 표시해 전체를 한 화면에서 비교한다. 완료 시각과 계정은 각 신문사의 도움말 및 접근성 이름으로 확인할 수 있다.

DB 버전 1·2는 시작 시 버전 3으로 올린다. 버전 3은 계정의 근무자 연결과 과월호 테이블만 추가하며, 기존 시간표·태깅·계정 기록은 보존한다. 구버전 이미지로 되돌릴 때는 DB 버전 호환성을 확인하고 배포 전 백업을 함께 복원한다.

수동 배정은 관리자만 가능하다. 담당자를 바꿔도 기존 신문사 항목의 ID·완료 상태·완료 시각·체크한 계정은 모두 유지되며, 새 담당자에게 수정 권한이 넘어간다. 비활성 근무자의 기존 배정은 그대로 보관할 수 있지만 새 배정은 재직 근무자에게만 할 수 있다. 다른 관리자의 배정 변경을 감지하면 저장을 거절해 덮어쓰지 않는다. 이 변경은 DB 스키마를 바꾸지 않는다.

PC 화면(901px 이상)은 80% 배율로 표시한다. 시간표는 별도로 행 높이와 이름 크기를 늘리고, 1001px 이상에서는 왼쪽에 넓은 시간표·오른쪽에 작은 주당 근무 시간 표를 배치한다. 좁은 화면은 세로 배치하며, 휴대폰·태블릿(900px 이하)은 기존 배율과 요일 선택을 유지한다.
